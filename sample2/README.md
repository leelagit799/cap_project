# DischargeFlow — Agentic AI Hospital Discharge Capstone

This implementation follows `FA5_SP_Interns_Capstone_AI_Discharge_Summaries.docx`: it ingests the supplied multilingual patient packets, validates them against the Mock EHR and `configs/rules.yaml`, applies guardrails, produces audits, supports HITL corrections, and answers record-grounded questions.

## Run the complete system

Python 3.11+ is recommended. From the project folder:

```bash
pip install -r requirements.txt
python run.py
```

Open these local services:

| Service | URL | Purpose |
| --- | --- | --- |
| Host Orchestrator | http://localhost:8083 | Gradio workflow runner, streaming summary and RAG views |
| HITL Dashboard | http://localhost:8501 | Five-page Streamlit clinical review workspace |
| Mock EHR | http://localhost:8050/docs | Patients, medication, allergies, labs and care plans |
| Primary MCP | http://localhost:8200/clinicaltools | Tools, resources, prompts, sampling, elicitation and roots |
| Analytics MCP | http://localhost:8201/analyticstools | Risk scores, benchmarks and heatmap |

`Ctrl+C` stops all services. The earlier single-screen prototype can still be run separately with `python app.py` at port 8080.

## API keys

No keys are needed to run the supplied sample data. The local pipeline uses deterministic, auditable extraction, normalization and FAISS retrieval. To enable live LLM sampling through LiteLLM/Agno or LangFuse delivery, copy `.env.example` to `.env`, provide the appropriate credentials, and export them in your shell before starting the services. Never put secrets in source code.

## Implementation map

| Requirement | Implementation |
| --- | --- |
| File monitor + Roots safety | `hospital_ai/mcp_primary.py` `clinical_watcher`; validates paths with `Path.relative_to()` |
| LangGraph extraction/normalization/validation | `hospital_ai/agents.py` with `StateGraph` and `MemorySaver` |
| Google ADK monitor/summary/host definitions | `hospital_ai/adk_agents.py` (enabled when `GOOGLE_ADK_MODEL` credentials are configured) |
| MCP primary + analytics servers | `hospital_ai/mcp_primary.py`, `hospital_ai/mcp_analytics.py` |
| All MCP primitives | Resources/prompts/tools plus sampling preferences, elicitation schema and root-safe watcher in the primary server |
| Mock EHR REST API | `hospital_ai/ehr_api.py` |
| A2A cards/auth/streaming | `hospital_ai/a2a_server.py`; ports 8100–8105 and `X-Agent-Auth-Token` |
| FAISS and Agno RAG roles | `hospital_ai/rag.py`; SQLite session configuration, `MultiMCPTools`, optional async `arun()` path |
| HITL dashboard (5 pages) | `hospital_ai/dashboard.py` |
| JSON/HTML reports + audit trail | `data/reports/`, generated by `hospital_ai/pipeline.py` |
| RAI guardrails | `hospital_ai/guardrails.py` for PII redaction, injection detection and grounding checks |
| LangFuse observability | `hospital_ai/observability.py`; safely publishes trace/event spans when credentials exist, with a JSONL audit fallback |

## Data and audit records

Input documents are preserved in `Data/incoming/`. Generated reports, review feedback, traces and logs are written to `data/reports/`; FAISS case indexes are written to `data/vector_db/`. Neither workflow overwrites clinical source documents.
